# Quality Visuals by AethDesign

A starting frontend and landing-page baseline, informed by annotated ServiceFlow examples. It is not an exhaustive design system, an authorship detector, or evidence that the earlier benchmark designs satisfy it. Frozen benchmark outputs and grades remain unchanged.

The authoritative [visual module](../assets/modules/visuals.md) supplies the rules. The [independent visual audit protocol](../references/VISUAL_AUDIT.md) defines evidence, findings and correction. [Download the instruction pack](downloads/quality-visuals-by-aethdesign.zip) or [choose a composed selection](MODULES.md).

| Avoid | Build instead |
| --- | --- |
| Slogan eyebrows that restate a heading | Specific headings; labels only when they add needed context |
| Arrows on every redirect, decorative icons/numbers | Meaningful affordances and genuine sequences |
| Half-empty cards, nested boxes, automatic bento grids | Containers chosen for the information and task |
| Reassurance bands, generic process/FAQ/closing sections | Content that resolves a decision or enables an action |
| Oversized gaps and repeated CTAs filling thin pages | Deliberate rhythm and proportionate useful content |
| Generic slogans, unrelated artwork, fabricated trust | Business-specific language, relevant imagery and verified facts |
| Authored UI prose with em/en dashes | Ordinary punctuation |
| Happy-path desktop screenshots as completion evidence | Desktop/mobile composition, relevant states and working interactions |
| Missing ownership/privacy links or invented legal details | Accurate relevant information based on the actual business/data/deployment context |

New frontends/pages and substantial redesigns require fresh independent visual review. Declare that scope with `./quality audit-packet --visual --criteria "Observable product and visual outcomes"`; instruction-only users supply the raw scope and evidence directly. Actual scope governs even when the flag is omitted. Isolated low-risk copy/static-style changes retain their focused builder lane.

Findings need the requirement, screen, viewport/state and observable evidence. Blocking baseline issues must be fixed, re-rendered and independently re-reviewed before completion. An average score cannot conceal blockers. Missing required render, interaction or review evidence is BLOCKED. Legal/privacy requirements depend on the actual context; agents must not fabricate business facts to clear a gate.

Purposeful whitespace, useful cards, necessary category labels, genuine numbered steps and deliberate brand expression remain valid. User-approved exceptions must be explicit. The standard should improve judgment rather than replace one generic template with another.
