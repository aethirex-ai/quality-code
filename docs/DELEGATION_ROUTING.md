# Why ServiceFlow used the same model

The recorded adaptive run selected one fresh backend helper on `gpt-6.1-sol` at medium effort. Its primary and auditors used the same model at high effort. The supplied native catalogue also advertised the cheaper `gpt-6-luna`; the supplied price evidence distinguished their rates. The run did not record a rejected model override or a failed cheaper-model attempt. Actual routing and usage remain in the [unchanged measured case](../benchmarks/serviceflow-mvp-2026-10/RESULTS.md).

The builder's routing note grouped authentication, persistence, business rules, AI adapters and HTTP/mock tests under one backend owner. It justified the model as appropriate for a critical, coupled authentication/state outcome and explicitly declined the cheaper easier-task model for that boundary. Lowering effort did not change the model or its API price tier. This was an ownership/model-selection decision; no observed runtime prohibition explains it.

## Policy gap and correction

The prior standard already required native discovery and the least costly qualified fit, but allowed a broad assignment and its project risk to supply the qualification argument. The inference is that this encouraged conservative selection for the whole backend, without evaluating worthwhile bounded implementation outcomes inside it. The record does not establish that any cheaper model would have passed those tasks.

The new provider-neutral policy requires checking a large default-model bundle for bounded, independently testable implementation outcomes before assigning it. Each worthwhile outcome compares accessible cheaper candidates using native capability/tool/cost evidence. Rejecting them requires task-specific requirements, failures or a concrete reason no useful smaller outcome exists. Product risk and independent gates remain unchanged. A qualified owner retains security architecture, contracts, integration and review; continuous visual ownership remains intact. Uncertain capability is disclosed, and no cheap-model quota or automatic fan-out is introduced.

Requested and observed model/effort settings are recorded separately. Model overrides use supported fresh scoped contexts when a history fork would inherit settings. See the [native subagent configuration documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents) for the host's controls; the standard itself does not encode provider or model identifiers.

## Before another measured trial

Freeze the revised policy and common task before either condition starts. Retain the same acceptance basis, independent audits, iteration taxonomy and native request-level accounting. Inspect the routing note for actual work units, candidates and rejection reasons. Verify actual native model/effort, rather than claiming cheaper delegation from a requested name or lower effort. If adaptive again finds no suitable cheaper outcome, report that decision and its evidence; do not relabel it as a cheaper-model test. Do not impose new stage deadlines or manufacture a team to satisfy the experiment.

This correction changes future policy delivery. It does not alter ServiceFlow's sources, findings, timing, counters or visual scores, and does not establish savings without another observed trial.
