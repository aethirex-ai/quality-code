01

The problem

“Done” needs a definition.

A coding agent can finish a task without sharing the project’s quality bar. Architecture is scattered, a passing build is mistaken for behavioral evidence, and changes receive either too little review or unnecessary ceremony.

Quality Code makes the contract explicit before implementation: what matters, which evidence is needed and where independent scrutiny belongs.

02

The system

One workflow. Clear boundaries.

01 / Context

A compact map.

MAP.md records ownership, interfaces and invariants. Agents read the relevant sections rather than loading an entire inventory.

02 / Verification

Risk sets the bar.

Configured checks turn acceptance criteria into observable evidence. The highest applicable risk wins.

03 / Independence

A fresh second layer.

High-risk work produces a bounded audit handoff for a fresh reviewer. Missing evidence stays visible as BLOCKED.

04 / Preservation

Adopt, never overwrite.

Existing project context is preserved. Unrelated runtime files and wrappers are treated as collisions.

03

The quality contract

Small changes stay small.

RiskBuilder evidenceIndependent review
LowOne focused confirmationOnly when requested
NormalRelevant regression and changed-scope checksWhen requested or risk increases
HighFocused tests and full verificationRequired
CriticalFull, release and applicable recovery evidenceRequired

A passing command is evidence, not proof that a product is correct. An audit packet is a handoff, not a verdict.

04

Inspectable evidence

Review changed the toolkit.

Independent review of the initial public edition found concrete defects. Each correction retained a regression test.

FindingCorrection
Adoption collisionsPreflight runtime, schema and license files before project writes.
Parent Git scopeConfine changes to the project and emit project-relative paths.
Mixed-path routingResolve each file’s effective route before selecting the highest risk.
License distributionRetain LICENSE in installed and generated tooling.

The initial re-audit returned PASS after reproducing these fixes and running the then-current 19 tests. This is historical toolkit evidence, not a claim of reduced defects in client products.

05

Use it

Make the process inspectable.

git clone https://github.com/aethirex-ai/quality-code.git
cd quality-code
python3 scripts/quality_code.py adopt /path/to/project

Python 3.11+, Git and a POSIX shell are required. Tailor the generated map and verification commands to the real project before relying on them.

06

Honest boundaries

A contract, not a guarantee.

The toolkit provides executable checks and an explicit review process. It does not guarantee agent compliance, enforce merge protection or prove measurable improvements in delivery speed and production defect rates.

Project-specific test quality, live providers, Windows shell behavior and deployment controls remain outside its guarantees. The installer is not transactional; configured commands run with the user’s permissions.
