# Quality Code project map

Last verified: 2026-10-14

## Product boundary

A Python bootstrap/verification toolkit and three composable AethDesign standards: Code, Visuals and Swarms. Canonical policy fragments: `assets/modules/`; `assets/project/AGENTS.md` is their generated full composition. `scripts/build_standard_packs.py` produces deterministic instruction-only ZIPs in `docs/downloads/`. Canonical engine: `scripts/quality_code.py`; installer: `scripts/install.py`; templates: `assets/project/`. Public explanation: `README.md` and `docs/`; `docs/index.html` is the static branded reader edition. `benchmarks/landing-pages-2026-10/` owns a recorded native-agent pilot and offline instrumentation; `docs/benchmarks/` serves its frozen fictional portfolios. `benchmarks/client-pilot-round2-2026-10/` owns the new-client follow-up and isolated seeded-defect review; its published oracle is excluded from timed solver workspaces. `benchmarks/rich-client-pilot-2026-10/` owns the richer two-client cheaper-owner pilot, immutable evidence, MIME-corrected evaluator and independently classified corrections; matching `docs/benchmarks/` serves four frozen three-page client experiences. `benchmarks/portal-pilot-2026-10/` owns the paired local client portal protocol, corrected capability isolation, frozen source/captures, independently classified defects/corrections and native accounting. Its gallery serves screenshots; no Python backend is deployed. `benchmarks/portal-completion-round2-2026-10/` preserves the brand-grounded follow-up with gates inside the budget, capped/incomplete outcomes, qualified diagnostic probes and token uncertainty. `benchmarks/serviceflow-mvp-2026-10/` owns the uncapped matched ServiceFlow MVP experiment, portable instruments, scoped controller amendments and explicit source projections; its paired apps run locally and its public gallery serves frozen screenshots. No production service or customer data.

## Runtime flow

CLI arguments → project detection → template merge or TOML routing → local verification / JSON audit packet. Installation → global agent instruction blocks / skill copies / launcher symlink.

## Ownership

AethDesign maintains the standard and public edition. `scripts/` owns behavior; `assets/` owns project defaults; `references/` and `SKILL.md` own independent review instructions; `tests/` verifies contracts. `.quality/quality.py` is a generated copy of the engine and must match it.

## Contracts and state

CLI subcommands: init, adopt, upgrade, validate, verify, context, audit-packet. TOML configuration version 1, standard version 3. Audit result schema version 1. Optional `quality_modules` selects policy; absent means all. Explicit selection replaces; unflagged upgrade preserves. One managed block/foundation per composition. `audit-packet --visual` declares the selected visual gate without altering code risk. Project instructions preserve unmanaged text; map/testing merges preserve existing sections. Installer updates home configuration and creates a checkout-linked launcher.

## Security, privacy, and safety

Verification runs configured executables with user permissions. No sandbox. Preserve existing content and refuse an unmanaged wrapper. Do not publish private paths, credentials, local settings, or customer data. Installer is not transactional; document its writes and collision behavior.

## Change invariants

- Highest specific matched risk wins; fallback covers unmatched paths.
- Missing required evidence is not a passing audit.
- Builder verification cannot replace required independent review.
- Delegation uses native discovery, bounded implementation candidate comparison and observed-setting checks; product risk does not alone determine model capability. Model/effort policy remains provider-neutral.
- Keep engine/local copy and schema/template copy identical.
- Distribution copies retain LICENSE and exclude Git history, local state, tests, and public documentation.

## Verification

`./quality validate` checks structure. `./quality verify full` runs offline stdlib unit/integration tests, distribution synchronization and documentation checks, and Git whitespace checks. Fast and changed profiles also run toolkit tests because the engine is small. Full/release use `scripts/check_serviceflow_regressions.py` for one dated, documented timing-test quarantine and deterministic replacement; frozen benchmark files stay unchanged. Release uses the full profile; it performs no remote writes.

## Do not edit casually

Bootstrap, upgrade, installer, configuration defaults, agent policy, and CI affect preservation or public behavior. Independent audit required. Public publication is explicitly authorized by the repository owner for this initial edition.

## Context routing

`.quality/quality.toml` routes tooling and instructions to high risk and CI to critical risk. Default documentation is normal. Audit packets are temporary handoffs outside committed source.

## ServiceFlow visual baseline follow-up

`benchmarks/serviceflow-visual-baseline-2026-10/` owns sanitized method, UI-only source deltas, review summaries and offline publication checks. Its `docs/benchmarks/` gallery separates originals, first reported handoffs and final accepted results. Final status stays pending through supplemental content corrections and independent re-review. Different starting apps and one observation each prevent causal baseline, swarm or winner claims. Raw native sessions and runtime harness remain private; public hashes and projections are explicit.
