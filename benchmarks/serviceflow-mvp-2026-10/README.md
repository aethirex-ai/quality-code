# ServiceFlow: an uncapped full-stack MVP comparison

Two native coding sessions implement the same fictional home-services product from the same blank fixture and acceptance basis. Both use Quality Code. One implements without delegation; the other may choose an adaptive team. This compares those two observed workflows, not Quality Code against its absence.

The product includes customer enquiries, role-protected dashboards, an enforced status workflow and activity history, admin service management, mature authentication, SQLite persistence and editable offline reply drafting. The business is fictional; AethDesign is the software-development and UI/UX design studio conducting this experiment.

## Completion protocol

There is no elapsed-time deadline, stage timeout, token quota or audit-round cap. Time and reported native usage are observations. Builders validate their work; fresh independent auditors review the complete agreed scope. Blocking findings return to the original builder session, followed by a fresh full independent audit. A builder or workstream director cannot supply its independent verdict.

The implementation and audit models use matched supported native settings. Adaptive delegation is optional: a persistent primary owns the visual experience and integration; a helper is justified only for a coherent independent outcome. Actual routing and effort are reported from native evidence, without substituting intended routing for observed behavior.

## Run the products locally

Each accepted app has its own README, lockfile, schema/migrations, seed script and demo credentials. Follow that app's exact setup commands in a separate directory. Use sample data only. No paid service or API key is needed. Reply drafting has a deterministic, visibly labeled demo fallback and never sends a message. Tests exercise the optional provider boundary with mocks; no configured live AI service is verified or charged here.

The gallery serves screenshots only. GitHub Pages does not run either authenticated server or database. These are experimental portfolio MVPs, with sampled independent acceptance evidence rather than production security certification.

## Evidence boundaries

The public source projections retain exact bytes from immutable source inventories. Runtime databases, generated authentication secrets, dependencies and benchmark-only handoff/routing reports are excluded before reading their bytes. Projection manifests disclose each exclusion and retained hash. Initial sources are retained separately from the accepted final sources.

Raw native sessions, cookies, private paths, generated credentials and internal report transcripts remain private. Published accounting, iteration classifications, audit summaries and capture manifests use explicit field allowlists. Instrument amendments preserve earlier evidence and disclose their scope; they do not erase failed or invalid audit rounds. Outer preparation, orchestration, comparative grading and publication work are excluded from subject totals and are not free.

Builder handoff READMEs are retained unchanged and may say the independent gate is pending. Final accepted verdicts are recorded in [app-audits.json](app-audits.json).
