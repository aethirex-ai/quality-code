# ServiceFlow verification

## Automated verification
Use Node 24.15+ and public npm registry. `npm ci --cache .npm-cache` installs locked dependencies. `npm test` runs real HTTP/SQLite tests plus two focused configured-payload privacy tests through `node --import tsx --test`; no external model calls. `npm run typecheck` checks all frontend/backend/shared/test TypeScript. `npm run build` checks types and compiles production frontend. `./quality verify full` runs application tests, the clean-artifact Python regression, typecheck, formatting and whitespace; `./quality verify release` runs production build, fresh-database setup and whitespace. Critical risk applies to every changed path.

HTTP tests allocate free ports and temporary fresh databases with synthetic secrets and actual Better Auth email/password login. They verify disabled signup/role tampering, session/role/ownership reads/writes/draft restrictions, cross-origin rejection, validation/normalization, exactly-once retries, stale conflicts, allowed/rejected transitions, chronological atomic actor history, admin-only service CRUD, deactivation/referenced deletion/history snapshots, catalogue action records, deterministic and mocked configured AI success/errors/privacy/question bounds, seed idempotency and persisted cookies/state after application restart. Expected 4xx negatives are successful assertions, not product defects.

The AUD-001 regression in `tests/drafts-privacy.test.ts` reproduces lowercase known-contact-name leakage before repair and asserts no capitalization variants remain in serialized configured-provider payloads. Coverage includes repeated/mixed capitalization, regex punctuation treated literally, short valid names and Unicode case matching. Fetch is always mocked; useful job/service details must remain. Run it alone with `node --import tsx --test tests/drafts-privacy.test.ts`.

The AUD-002 regression in `tests/backend.test.ts` creates real HTTP requests using accepted seven/eight-digit and formatted phone values, calls the staff draft endpoint, and inspects the mocked serialized provider body. Seven cases cover plain, formatted, alternate separators and a longer-number control; useful job details/date/service remain, original persisted phone/description remain, and drafting adds no status/history mutation. Run it alone with `node --import tsx --test --test-name-pattern AUD-002 tests/backend.test.ts`.

## Local setup and browser verification
Run `npm run migrate`, `npm run seed`, `npm run build`, then `PORTAL_PORT=3000 npm run benchmark:start` (use supplied PORTAL_PORT for benchmark). `python3 preview_client.py --ready` checks bridge readiness only. `npm run test:e2e` requires the supplied bridge and running app at its assigned port. It performs a real customer form submission followed by provider update/history/draft and customer ownership confirmation. Actions use `{ "op": "click", "selector": "..." }` (fill/select add value), bounded to 24 per journey. No arbitrary browser JavaScript, external access or cookie bypass.

Inspect returned screenshots using native image tooling at both 1440 and 375 widths. Bridge records document width, overflow, browser errors and blocked requests. A screenshot or metadata alone is not a functional verdict: assertions check page content and failed actions, and HTTP tests confirm committed state. Screenshots/journey results are saved in evidence/browser-results.json; commands and failures are retained with `qa_check.py` in frontend/backend/integration check-runs.jsonl. Defect/tooling/visual correction records live in evidence/issues.jsonl. Runtime artifacts are ignored by Git but remain in the workspace for audit.

## Clean artifact and catalogue boundary regressions

`npm run test:browser-artifacts` runs `tests/browser_artifacts_test.py` against an isolated empty directory. It verifies generated action JSON exists before bridge invocation and repeated renders overwrite actions and retain results. This test is included in the full profile. The real documented `npm run test:e2e` was also run with `scripts/browser-actions` absent; it created its artifacts and passed all 12 journeys. Earlier generated actions were preserved under evidence, not deleted. A bridge and running app remain required.

`npm run test:catalogue-boundaries` authenticates as the synthetic admin, creates the reported 99-character service name through the real API, and verifies settled public/admin renders at 375 and 1440. It also tests maximum 100-character name, 700-character description and 100-character price labels on mobile. Input limits remain unchanged. It rejects horizontal overflow, browser/blocked-request/action errors; inspect saved screenshots to confirm wrapping and visible controls. Temporary unreferenced services are deleted through the authorized API in cleanup. Results/attempts persist in `evidence/catalogue-boundary-*.json`. Run this alongside the core E2E command before audit handoff.

## Audit gate
Generate `./quality audit-packet --criteria "<full observable criteria>"` after full/release/browser checks. Parent supplies a fresh independent full-scope auditor and returns findings to the persistent builder. Builder never claims independent acceptance. Browser bridge absent is a concrete unverified browser gate, never silently replaced by DOM or build checks.
