# ServiceFlow project map

## Product boundary
One fictional Bristol home-services business, Hearth & Home. AethDesign is the software-development and UI/UX studio behind this portfolio demonstration, not the service business or a claimed client. No live scheduling, multi-tenancy, matching, marketplace, payments, email/SMS, uploads, deployment or live AI in verification. Reference material and benchmark helpers remain unchanged.

## Runtime flow
React + TypeScript + React Router in `src/client/main.tsx`, one continuous visual owner; shared UI components and responsive CSS in `src/client/styles.css`. `src/client/api.ts` handles typed same-origin JSON calls and safe error envelopes. Shared role, request, service, history and draft contracts in `src/shared/contracts.ts`. Express 5 in `src/server/app.ts` exposes `/api/me`, `/api/services`, `/api/requests`, per-request detail/status/draft endpoints and Better Auth `/api/auth/*`. `src/server/index.ts` binds only the configured loopback port; Vite middleware in development, built static SPA with self-only CSP in production. No external fonts/assets. Catalogue tracks/cards constrain widths and wrap valid long content.

## Ownership
`/root` owns all product visuals, frontend, contracts, integration, observable browser validation and documentation. `/root/backend` owns the coherent auth/persistence/business/AI backend and HTTP tests. `ROUTING.json` records discovery and actual context/model decisions. Independent audit is parent-orchestrated, pending at builder handoff; neither builder provides an independent verdict.

## Contracts and state
Better Auth controls hashing, session cookies and auth migrations. Database-managed roles have `input:false`; public signup disabled. Two customers, one provider and one admin are seeded by a separate local command. SQLite `node:sqlite` uses foreign keys, WAL and explicit transactions. Versioned domain migrations under `migrations/` create services, requests, request activity, catalogue activity and operations; `schema_migrations` tracks versions. Requests snapshot service name/price, so edits/deactivation leave history intelligible. Referenced services cannot be deleted. Only active services can receive new requests.

Customers create requests and read only their own lists/details/history. Provider/admin read and manage all requests for the single business; only admin writes catalogue. Workflow: New → Reviewing → Quoted → Booked → Completed. Declined from New/Reviewing/Quoted only; terminal states reject further moves. Version checks reject stale updates. Every committed request/status/catalogue action includes actor and timestamp atomically; rejected actions roll back. Actor-scoped operation keys replay the same normalized write without duplicates and reject reuse with changed content. The browser stores request form + operation key in sessionStorage until acknowledged; status keys include request/version/destination.

`src/server/drafts.ts` provides deterministic unsent draft fallback and a separately configured OpenAI-compatible provider. Key/model/URL are server env only; tests inject mocked fetch. Payload excludes contact fields and location, redacts literal known names case-insensitively (including valid short names), known contact-phone digit sequences across validated lengths and common formatting, plus email/general-phone/postcode patterns in description. Draft requires staff authorization, at most three questions, explicit review label and no status/history mutation; no send action exists.

## Security, privacy, and safety
Critical risk for auth/ownership/persistence. Every business endpoint enforces session and role server-side. Mutations require exact allowed Origin + JSON; Better Auth protections remain enabled. API responses are no-store. Zod strict schemas trim/normalize input and validate calendar dates, phone digits, bounds and date range. React escapes untrusted strings. Safe errors never include stacks/upstream provider details. Local generated auth signing secret is persisted beside database with mode 0600, excluded by gitignore; env override supported. No secrets are logged or exposed to the client.

## Change invariants
Preserve supplied instructions, frozen brand files, helpers and protected measurement corpus. Critical full/release route cannot be lowered. Retain failures and correction/recheck evidence. No independent self-audit acceptance or live integrations.

## Verification
`tests/drafts-privacy.test.ts` exercises the outgoing configured-provider serialization with capitalization/literal/short-name regressions (mocked only). `tests/backend.test.ts` uses actual ephemeral HTTP listeners, Better Auth cookies, isolated migrated/seeded SQLite fixtures and mocked AI adapters. Covers validation, normalization, roles, ownership, workflow/terminal/stale rejection, retries, atomic history, catalogue preservation, persistence across app restart, seed idempotency and HTTP-accepted short/formatted phone privacy at mocked provider serialization. `scripts/browser_checks.py` initializes ignored action directories and drives core browser journeys. `tests/browser_artifacts_test.py` checks clean/repeated artifact creation; `scripts/catalogue_boundary_checks.py` verifies accepted long-name/text limits in settled public/admin mobile/desktop renders. QA command output in owner check-runs; issue lifecycle in evidence/issues.jsonl. Full: application tests + artifact regression + typecheck + formatting + whitespace. Release: production build + fresh setup. Browser journeys recorded separately against running production app. Final gate remains fresh full-scope independent audit by parent.
