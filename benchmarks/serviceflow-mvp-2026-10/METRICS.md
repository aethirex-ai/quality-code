# Measurement definitions

The population is one ordered pair of implementations of the same ServiceFlow prompt and frozen acceptance basis. The adaptive condition is permission to choose delegation, not a required number of helpers or a forced hierarchy. Both subjects receive Quality Code; the single implementation cannot delegate. Independent product auditors are outside that implementation topology restriction and their reported usage is included.

## Completion and time

Initial handoff is the original builder's completed native turn. Accepted completion requires the original builder's repairs and a fresh full-scope independent PASS against the common criteria, with required verification and source integrity intact. A builder's own passing checks or a structural deliverable check cannot establish acceptance. The original single auditor's obsolete scope metadata is retained as an invalid canonical report; its actual reproductions can inform repair, and a new correctly scoped full audit is required.

Calendar time runs from condition start through final verification/cleanup and includes controller gaps. Recorded controller execution intervals exclude the separately recorded orchestration gap; they are elapsed intervals, not CPU time. Phase durations are a further decomposition. Conditions can overlap after controller recovery, and other account work can affect service capacity. Neither time measure proves a causal speed advantage. No elapsed limit or audit-round ceiling ends implementation or repair.

## Native usage and conditional API equivalent

Count each explicitly owned native root and descendant once. Original builder resumes share one cumulative root; phase deltas reconcile against native before/after snapshots and CLI completion counters. Every audit and repair, including the invalid-format auditor, remains included. Cached input is a subset of input. Reasoning tokens, where reported, are a subset of output. Neither subset is added to the total again. Missing or inconsistent evidence withholds exact totals/prices rather than becoming zero.

For mixed context tiers, each positive cumulative native token-count increment must equal the corresponding last-request usage, and those requests must sum exactly to the session total. Assign the applicable tier from that request's input count and the retained threshold, then sum request-level components. Exact builder resumes remain one cumulative session. A session with any long request cannot be priced entirely at the ordinary rate; preserve the ordinary-rate collector's withheld field alongside independently reconciled mixed-tier estimates.

For a supported ordinary-context rate: `(input - cached_input) × ordinary_input_rate + cached_input × cached_input_rate + output × output_rate`, divided by one million. Cache-writing or other unreported categories are not invented. Apply model-specific and context-tier eligibility from the retained pricing evidence. This is a conditional public API-price equivalent of reported native counters, not an invoice or subscription consumption conversion. Setup, preflight, outer orchestration, final comparative grading and publication work are outside measured subject totals and are not free. The experiment does not use account percentages, account resets or live AI drafting calls.

## Product defects and iterations

An observed failed assertion is not automatically a distinct product defect. Use the independent evidence classification: product defects, visual refinements, tooling/environment errors, construction/type failures, expected negative tests and duplicate manifestations remain separate. Count a product correction cycle only when a demonstrated defect, corrective change and relevant recheck are evidenced. A check rerun, model turn or additional assertion is not another correction cycle. Shared root causes count once with their manifestations recorded; incomplete evidence stays unknown.

Independent audit findings describe defects actually detected in the reviewed app and scope. This is not a hidden-oracle defect-recall experiment, a count of every latent bug, a production security certification or proof that one condition is generally better at error finding. Test counts are reported as evidence, never as a normalized backend quality score.

## Frontend and backend quality

Backend completion uses the same observable acceptance contracts: fresh setup/authentication, role/ownership enforcement, validation/workflow, catalogue permissions, history/transaction safety, server-only editable draft behavior and persistence. A passing audit establishes only the checked local MVP scope.

Final comparative visual review uses anonymous matched desktop/mobile screenshots from immutable accepted copies. It is separate from the product audit and cannot repair the measured app. Screenshot judgments cannot certify keyboard behavior, runtime accessibility or security. Preserve category judgments and visible evidence rather than convert them into an overall engineering superiority claim.

## Interpretation

Report actual models, effort and topology from native evidence. A permitted cheaper model or a routing self-report is not proof that a cheaper model executed. One pair, subjective visual judgments, infrastructure amendments, source-projection exclusions and possible timing overlap limit generalization. Retain unfavorable outcomes and costs; do not select only successful phases.

The optional legacy iteration summarizer requires an `owner` field that the measured stable-ID issue records did not supply. `postprocess.py` preserves native accounting and marks only this optional parse as `unparsed`, with null counts and unchanged raw evidence referenced for independent `iteration-review.json` classification. It never substitutes zero or normalizes records. Other accounting/source errors remain failures. This compatibility helper runs only after final metadata and is separately hashed postprocessing work; see `POSTPROCESSING.md`.
