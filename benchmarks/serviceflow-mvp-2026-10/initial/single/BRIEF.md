# ServiceFlow common acceptance basis
Both subjects receive the same APP_PROMPT.txt and frozen AethDesign reference. Clean isolated starting fixtures; same model/effort for primary and independent auditor; only adaptive implementation may delegate. Stack choice is part of implementation judgment and must be reported as a possible comparison confounder. No time or round caps; no mandatory swarm. No live AI/provider/account/subscription calls.

Required observable outcomes:
1. README fresh setup installs pinned dependencies, migrates relational database, seeds four role/ownership demo users and runs app; production build and real full/release profiles pass.
2. Authentication uses a mature library and each role reaches appropriate views; unauthorized/unauthenticated writes and cross-site writes fail through server enforcement.
3. Customer request validation, submission, own dashboard and persisted history work; second customer ownership isolation holds through direct route/API and draft endpoints.
4. Provider totals/search/filter/detail and permitted transitions work; invalid/stale transitions fail without partial state or successful history.
5. Admin catalogue CRUD/activation works; provider cannot manage services; inactive services cannot create requests and referenced service history survives deletion policy.
6. Deterministic no-key drafting works server-side, at most three useful questions, editable/review-labeled and no sending/status mutation; customer access fails; configured server-side adapter is implemented and tested with mocks only, secrets/PII not leaked.
7. Integrated customer-submit/provider-update journey works in a real browser; database/history survives reload/restart; committed-write/failed-refresh behavior is coherent and safe.
8. Real desktop/mobile landing, request form, customer dashboard, provider dashboard/detail/draft and admin service states show coherent identity, usable layout, labels, focus, keyboard behavior and no missing assets/runtime failures.
9. Every required verification step and full-scope fresh independent audit completes; blockers are repaired in the original builder session then reviewed by a fresh independent auditor. Missing evidence is BLOCKED, not PASS.

Record initial and accepted immutable source snapshots, actual topology/models/effort, native input/cached-input/output subsets without double-counting, all audit/repair rounds and evidence-backed defect/fix cycles. Clock initial implementation and end-to-end verified completion separately; retain transport interruptions and unknown usage. Frozen prior portal results are outside this experiment. Anonymous final visual grading is separate from app acceptance and cannot repair apps or change measured outcomes.
