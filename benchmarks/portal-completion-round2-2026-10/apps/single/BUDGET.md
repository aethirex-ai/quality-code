# One shared completion budget

Each subject gets90 minutes(5400seconds) across its entire coding/review tree: initial implementation, all descendants, context transfer, preview waiting, fixed contract checks, fresh independent audits, repairs, rechecks, packets and all owned cleanup. Initial builder phase is capped at40minutes(2400seconds), reserving at least50minutes for gates/corrections. Fresh audit phases are capped at20minutes, repair phases at15minutes, always constrained by remaining global time and30seconds cleanup reserve. Up to4 audit rounds is a ceiling, not a target. Completion requires a full independent PASS; exhausted caps or unavailable evidence are incomplete. Do not turn unused budget into manufactured work or fan-out.

Up to3 implementation helpers is a ceiling when native capacity permits; primary plus all descendants share capacity/budget. Single condition permits no implementation helpers. Each condition still receives fresh independent reviewers; these cannot have built/directed the changes and are included in both cost/time totals. Keep visual/integration ownership persistent across repair resumes. Reserve meaningful integration/visual validation before each audit-ready handoff. Join active helpers before audit.

Exact live native token quotas are unavailable: use conservative allocations and report uncertainty. Parent shared setup, native capability preflight, final comparative/anonymous scoring and publication are reported separately and excluded, not free. Per-condition parent gate checks and native auditors ARE included in completion elapsed, and all native coding/review sessions/descendants in tokens/API equivalent. Initial-ready and accepted-or-capped stages are separately retained. No subscription conversion or claim.
