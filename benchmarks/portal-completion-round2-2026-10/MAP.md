# Completion benchmark map

## Product boundary
Matched fictional AethDesign software and UI/UX client workspaces start from one frozen public brand corpus. Historical app outputs remain unchanged. This repository contains fixed Node/Python judges and native CLI orchestration; it contains no customer data or deployed backend.

## Runtime flow
prepare.py generates matching blank scaffolds. protocol.json seals the measured instruments and common corpus. run.py prepares a fixed-origin preview, then measures the initial builder, fixed contract gates, fresh independent native audits, exact-session repairs, confirmation and owned cleanup. Final comparative grading is outside the completion clock.

## Ownership
The primary owns brand, contract, protocol and integration. Scoped helpers own runner/accounting or evaluators. Preflight reviewers have no build ownership. Each application reviewer starts in a fresh separate session and never implements changes.

## Contracts and state
Each condition shares 5,400 seconds across all phases and descendants: initial build capped at 2,400; 3,000 reserved for gates; each audit capped at 1,200 and repair at 900; at most four audit rounds; 30 seconds reserved for cleanup. Protected corpus and editable tests/profiles are distinct. The critical auth/state route cannot be downgraded. Acceptance requires a complete canonical native PASS with actual full/release evidence, unchanged audited source and passing fixed gates. Resumes name the exact original builder; cumulative usage is counted once, plus descendants and fresh reviewers.

## Security, privacy, and safety
Preserve native workspace protections and localhost-only tool networking. Cleanup signals only owned process groups or listeners proven by kernel working directory and command. Read native bodies only for identified roots and descendants. Do not publish private session IDs, transcripts, cookies, databases or logs. Catalogs/prices are dated observations, not permanent model rankings in the standard.

## Change invariants
Never overwrite a started condition or its initial evidence. Report initial and accepted-or-capped measurements separately. Hash the common corpus and measured sources before launch. Repair findings and obtain fresh full-scope review. Preserve copied app and capture bytes; unknown usage, prices or gates remain unknown.

## Verification
Full/release profiles run offline instrumentation tests, preview contract tests and Git whitespace checks. Separate positive/negative controls cover backend boundaries, frontend journeys, cleanup, capture, Unicode and composed recovery. Native capability preflight checks real argument grammar, tool isolation, exact resume/counter reconciliation and structured output. Preparation is excluded and disclosed; CI profiles never make paid model calls.
