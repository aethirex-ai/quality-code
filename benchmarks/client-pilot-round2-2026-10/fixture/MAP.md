# New-client fixture map
## Product boundary
Three dependency-free static fictional client pages: hotel, studio, landscape. Root index links them. No production service or data.
## Ownership
Each page owner owns its complete HTML/CSS/JS/assets and focused tests. Primary owns root integration and image manifest.
## Runtime flow
HTML/CSS and local JavaScript demo interactions. No network state or persistence.
## Contracts and state
Reservation, estimate and class counter selectors/field names are fixed by BRIEF.md. Confirm demos safely with textContent.
## Security, privacy, and safety
Synthetic content, native image generation, no keys or real transactions. Do not read evaluator, outside siblings or unrelated logs.
## Change invariants
Preserve fixed brief and quality files; accessible responsive semantics and fictional attribution.
## Verification
Local structural/resource checks via verify_site.py; builder interaction checks; frozen browser evaluator and anonymous review after timed completion.

## Do not edit casually

- Security, persistence, release, and destructive paths require explicit risk routing.
- Public contracts and persisted state require compatibility evidence.
- Release and security changes require the release verification profile.

## Context routing

Detailed path-to-risk, test, and map-section routing lives in `.quality/quality.toml`. Update it when ownership or risk changes. Generated inventories must be regenerated rather than hand-edited.
